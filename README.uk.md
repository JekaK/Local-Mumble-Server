# Local Mumble Server

**Локальний голосовий сервер для класу або групи — на одному Android-телефоні, без інтернету.**

**Українська** · [English](README.md)

| Android | Версія | Голос | Мережа |
| --- | --- | --- | --- |

Телефон викладача запускає сервер і створює Wi-Fi-точку доступу. Учні
підключаються до цієї мережі та спілкуються через Mumble-сумісні голосові
клієнти. Викладач може одночасно говорити й слухати через окремий клієнт
на тому самому телефоні.

Під час роботи не потрібні інтернет, комп'ютер, окремий роутер, root або
Termux. Сервер і клієнти потрібно завантажити заздалегідь. Поточний інтерфейс
серверного застосунку — український; документація доступна двома мовами.

> **Статус beta:** автор проєкту підтвердив запуск сервера на фізичному
> Android-телефоні. Автотести нативного протоколу пройдені. Реальне аудіо,
> робота з повним класом та сумісність з iPhone ще не перевірені. Зависання
> iPhone-клієнта на «Connecting» залишається відкритим випадком діагностики.

## Для чого цей проєкт

Голосовий зв'язок у класі потрібен і тоді, коли інтернет відсутній або мережа
перевантажена. Local Mumble Server розміщує сервер на телефоні викладача та
передає голос між пристроями в одній локальній мережі.

Проєкт призначений для тестування голосових сесій у класах, шкільних укриттях,
майстернях і невеликих групах. Локальна передача прибирає залежність від
зовнішнього голосового сервера. Затримка все одно залежить від телефонів,
Wi-Fi, налаштувань клієнта та навушників. Гарантованої затримки або місткості
групи поки немає.

## Що вже реалізовано

- Нативний **uMurmur**-сервер, включений у APK.
- Запуск і зупинка; налаштування порту, пароля, кількості учасників і смуги пропускання.
- Спільний голосовий канал **Клас**.
- Робота через foreground service з постійним повідомленням і кнопкою зупинки.
- Відображення та копіювання локальних IP-адрес.
- Лічильник учасників через локальний UDP-запит.
- Журнал останніх 80 рядків із копіюванням.
- Окремий самопідписаний TLS-сертифікат для кожного встановлення.
- Вихідний код, ліцензії залежностей та автоматичні тести протоколу.

Сервер не використовує мікрофон і не записує аудіо. На **кожному пристрої,
який говорить або слухає, потрібен окремий голосовий клієнт** — зокрема й
на телефоні викладача. Проєкт використовує uMurmur, не MumbleWay, і не є
офіційним випуском команди Mumble.

## Вимоги

| Що | Вимога |
| --- | --- |
| Телефон із сервером | Android 8.0+; ARM64, ARMv7 або x86-64 |
| Локальна мережа | Wi-Fi-хотспот Android або наявна LAN |
| Робота хотспота | Підключені пристрої мають мати доступ до телефона-хоста |
| Голосовий клієнт | Сумісність із Mumble та підтримка Opus |
| Клієнт для Android | [Mumla](https://mumla-app.gitlab.io/), доступна на [F-Droid](https://f-droid.org/packages/se.lublin.mumla/) |
| iPhone | Потрібен сумісний iOS-клієнт; робота з цією збіркою ще не підтверджена |
| Інтернет | Для попереднього завантаження; для локальної голосової сесії не потрібен |

Виміряних мінімальних вимог до RAM і процесора поки немає. Починати потрібно
з двох пристроїв та поступово збільшувати навантаження на конкретному телефоні.

**Ліміт сервера не змінює ліміт хотспота.** Якщо телефон дозволяє 10
Wi-Fi-пристроїв, значення «30 учасників» не підключить 30 телефонів.
Голосовий клієнт викладача також займає один слот сервера.

## Яку адресу вводити

| Де запущений голосовий клієнт | Адреса сервера |
| --- | --- |
| На Android-телефоні із сервером | `127.0.0.1` |
| На іншому телефоні в хотспоті викладача | IPv4-адреса хотспота телефона викладача |
| На іншому пристрої в наявній LAN | IPv4-адреса Android-хоста в цій LAN |

Порт — **64738**, якщо його не змінювали. Адреса й порт вводяться в окремі
поля; `http://` або `https://` додавати не потрібно.

`127.0.0.1` завжди означає **цей пристрій**. На телефоні учня ця адреса
вказує на самого учня, а не на сервер викладача.

У хотспоті викладача IP телефона-хоста зазвичай показаний як **Шлюз / Router /
Gateway** у властивостях Wi-Fi на підключеному пристрої. У мережі з окремим
роутером це поле містить адресу роутера: там потрібно брати IP Android-хоста,
показаний серверним застосунком. Адреса хотспота залежить від телефона й може
змінитися після перезапуску точки доступу.

## Покрокове встановлення

### 1. Підготувати пристрої до роботи без інтернету

1. Завантажити [LocalMumbleServer-1.0.0-beta1.apk](https://github.com/JekaK/Local-Mumble-Server/raw/refs/heads/master/downloads/LocalMumbleServer-1.0.0-beta1.apk)
   на **Android-телефон викладача**.
2. Встановити [Mumla з F-Droid](https://f-droid.org/packages/se.lublin.mumla/)
   на Android-пристрої, які говоритимуть або слухатимуть. На телефон викладача — також.
3. Якщо братимуть участь iPhone, заздалегідь перевірити їхній клієнт на двох
   пристроях. Див. [розділ про iPhone](#підключення-iphone).
4. Підготувати навушники для пристроїв в одному приміщенні, щоб зменшити
   акустичний зворотний зв'язок. Спочатку перевірити один сервер і одного учня.

Учням потрібен **клієнт**, а не серверний APK.

### 2. Встановити серверний APK на Android

1. Відкрити завантажений APK у браузерних завантаженнях або файловому менеджері.
2. Якщо Android блокує встановлення, дозволити **Встановлення невідомих
   застосунків** для браузера/менеджера, який відкриває файл. Назви меню
   залежать від виробника телефона.
3. Встановити та запустити **Локальний Mumble сервер**.
4. Дозволити повідомлення, щоб бачити постійне повідомлення про роботу сервера
   та кнопку зупинки.
5. Після встановлення прибрати дозвіл на встановлення APK для браузера або
   файлового менеджера, якщо він більше не потрібен.

Готовий APK — **beta із debug-підписом**, не production-реліз. Для перевірки
цілісності доступна SHA-256 у [downloads/SHA256SUMS](downloads/SHA256SUMS).

### 3. Створити локальну Wi-Fi-мережу

1. Відкрити системні налаштування **Точка доступу / Модем** на Android-хості.
   У сервері є кнопка **Відкрити налаштування точки доступу**.
2. Задати впізнавану назву мережі, наприклад `Class-Voice`.
3. Встановити пароль Wi-Fi та увімкнути хотспот.
4. Вимкнути автоматичне вимкнення точки доступу, якщо таке налаштування є.
5. Підключити інший телефон. Якщо він пише **Немає інтернету**, залишити
   підключення до цієї Wi-Fi-мережі: для голосу потрібна локальна передача.
6. Мобільні дані для голосу не потрібні. Для перевірки без інтернету їх можна
   вимкнути, якщо телефон дозволяє залишити хотспот активним без мобільних даних.

Серверний застосунок відкриває системні налаштування, але не створює хотспот
автоматично. Можна також використовувати наявну LAN, якщо пристрої мають
доступ до телефона-хоста.

### 4. Налаштувати та запустити сервер

Початкові значення:

| Поле застосунку | Значення | Що означає |
| --- | --- | --- |
| Порт | `64738` | Спільний порт для TCP та UDP |
| Максимум учасників | `30` | Слоти сервера разом із клієнтом викладача; не гарантія місткості |
| Максимальний бітрейт… | `48000` | Серверний ліміт смуги на користувача, біт/с; службові дані пакетів також впливають |
| Пароль сервера | Власний пароль | Окремий від пароля Wi-Fi |

1. Задати пароль сервера та повідомити його учасникам.
2. Натиснути **Запустити сервер**.
3. Дочекатися напису **Сервер працює**. Перший запуск створює сертифікат і
   може тривати довше, ніж наступні.
4. Знайти рядок **Для учнів**. Якщо адрес декілька, використати ту, що належить
   мережі, до якої приєдналися учні.
5. Якщо Android не показує IP хотспота, взяти **Шлюз / Router** на підключеному
   пристрої за інструкцією вище.

«Сервер працює» означає, що нативний сервер відкрив TCP і UDP для приймання
підключень. Цей статус ще не доводить, що інший телефон може до них звернутися.

### 5. Підключити голосовий клієнт викладача

На Android-хості відкрити Mumla та додати сервер:

| Поле клієнта | Значення |
| --- | --- |
| Назва | `Class Voice` — будь-яка зрозуміла назва |
| Адреса / Host | `127.0.0.1` |
| Порт | `64738` або змінений у сервері |
| Ім'я користувача | `Teacher` або інше унікальне ім'я |
| Пароль | Пароль сервера з кроку 4 |

Підключитися до каналу **Клас**. Якщо клієнт показує попередження про
сертифікат, прийняти його **після перевірки, що це підключення до власного
сервера**. Самопідписаний сертифікат створюється на телефоні-хості та
використовується після перезапуску сервера. Перевстановлення або видалення
даних застосунку може змінити сертифікат.

Поки Mumla відкрита, сервер продовжує працювати через foreground service.
Сам сервер не просить доступу до мікрофона; цей доступ потрібен клієнту.

### 6. Підключити учнів або інших учасників

1. Приєднатися до `Class-Voice` за **паролем Wi-Fi**.
2. Залишитися в цій Wi-Fi-мережі, навіть якщо інтернет відсутній.
3. У голосовому клієнті додати сервер: **IP хотспота викладача** та порт `64738`.
   Не вводити `127.0.0.1` або власну IP-адресу учня.
4. Задати унікальне ім'я, наприклад `Student01`, і **пароль сервера**.
5. Перевірити сертифікат за інструкцією вище та підключитися до **Клас**.
6. Дозволити клієнту мікрофон, якщо учаснику потрібно говорити.
7. У навушниках перевірити голос в обидва боки, перш ніж додавати решту пристроїв.

### 7. Перевірити готовність до повної сесії

- Спочатку два пристрої: обидва мають чути та передавати голос.
- Розмістити телефон-хост так, щоб Wi-Fi-сигнал був стабільним.
- Перевірити роботу з відкритою Mumla, коли серверний застосунок у фоні.
  Окремо перевірити роботу з вимкненим екраном хоста.
- Якщо виробник пропонує режим батареї **Без обмежень**, застосувати його до
  сервера та клієнта. Політики енергозбереження все одно потребують перевірки.
- Додавати учасників невеликими групами; стежити за обривами, затримкою та нагрівом.
- Забезпечити заряд телефона-хоста; після заняття зупинити сервер і хотспот.

Для шумного приміщення підійде push-to-talk, якщо клієнт його підтримує.
Відлуння від сусідніх динаміків — окрема проблема, а не вимірювання мережевої затримки.

## Підключення iPhone

Серверний APK працює тільки на Android. iPhone може бути учасником **через
сумісний Mumble-клієнт**; його робота з цією beta поки не підтверджена.

[Mumble від Mikkel Krautz](https://apps.apple.com/us/app/mumble/id443472808)
має в App Store версію 1.3.1 від 13 вересня 2017 року.
[Репозиторій розробників](https://github.com/mumble-voip/mumble-iphoneos)
прямо вказує, що застосунок не підтримується. Наявність у магазині не
гарантує сумісності із сучасною iOS або цим сервером.

Якщо iPhone зависає на **Connecting**:

1. Перевірити підключення до хотспота викладача та адресу **Маршрутизатор / Router**.
2. Перевірити порт і пароль сервера.
3. Відкрити **Налаштування → Приватність і безпека → Локальна мережа** та
   дозволити клієнту доступ, якщо він є в переліку.
   [Інструкція Apple](https://support.apple.com/en-us/102229).
4. Перевірити, чи клієнт не очікує підтвердження сертифіката сервера.
5. Після повторної спроби відкрити **Журнал сервера** на Android.
   За конкретною помилкою відрізнити збій TLS, відхилений вхід або
   несумісність кодека. Сам напис «Connecting» не визначає причину.

Нативний сервер вимагає TLS 1.2 або новіший та заявлену клієнтом підтримку
Opus. Це вимоги сумісності, а не встановлений діагноз проблеми iPhone.
Без журналу причину повідомленого випадку ще не визначено.

## Діагностика

| Симптом | Що перевірити / зробити |
| --- | --- |
| APK не встановлюється | Android 8.0+, підтримувана архітектура, дозвіл на встановлення для застосунку, який відкриває файл, і повне завантаження APK |
| Сервер не запускається | Відкрити **Журнал сервера**; перевірити конкретну помилку; порт `1024–65535`, учасники `2–100`, смуга `8000–128000` |
| На хості працює, інший телефон пише Connecting | Wi-Fi, IP хоста, порт, підключення до мережі без інтернету, дозвіл локальної мережі та обмеження хотспота |
| `SSL handshake failed` | Збій TLS; зберегти числовий код і повний журнал; перевірити сумісність клієнта та підтвердження сертифіката |
| `Your client does not support Opus` | Клієнт не повідомив про підтримку Opus; потрібен клієнт/збірка з підтримкою цього кодека |
| `Wrong server password` | Ввести пароль сервера, а не Wi-Fi; після зміни пароля перепідключитися |
| `Username already in use` | Задати кожному клієнту унікальне ім'я |
| Не показаний IP | У хотспоті хоста взяти Шлюз/Router підключеного пристрою; у наявній LAN — адресу самого хоста |
| Підключення є, голосу немає | Канал **Клас**, mute/deafen, доступ до мікрофона, push-to-talk та вибраний аудіовихід |
| Голос переривається або сильно затримується | Спочатку перевірити два пристрої; покращити сигнал, порівняти аудіоналаштування, зменшити одночасних мовців і перевірити енергозбереження |
| Відлуння або свист | Навушники, push-to-talk та менша гучність сусідніх динаміків |
| Зупиняється у фоні / із заблокованим екраном | Обмеження батареї для сервера й клієнта, автоматичне вимкнення хотспота та постійне повідомлення |
| Нові телефони не приєднуються до Wi-Fi | Ліміт клієнтів самого хотспота; кількість слотів сервера його не збільшить |
| Лічильник показує помилку UDP | Не відповів локальний UDP-запит застосунку; перевірити журнал; це не тест доступності з інших телефонів |

Для повідомлення про проблему відтворити її та відкрити **Журнал сервера →
Копіювати**. Додати модель хоста/версію Android, назву/версію клієнта, тип
мережі, точну помилку та результат підключення до `127.0.0.1` на хості.
Перед публікацією прибрати паролі та особисті імена. Відсутність нового
рядка не доводить, що TCP-з'єднання не дійшло: частина ранніх подій
не записується у звичайному рівні журналу.

## Щоденна робота та дані

- Зупинка — у застосунку або постійному повідомленні.
- Зміна параметрів: зупинити, відредагувати, запустити знову.
- Перезапуск телефона не запускає сервер автоматично.
- У журналі зберігаються не більше 80 рядків; аудіозаписів немає.
- Пароль, конфігурація, сертифікат і приватний ключ — у приватному каталозі
  застосунку. Резервне копіювання застосунку вимкнене.
- Аналітики або запитів до зовнішніх сервісів немає. Android-дозвіл `INTERNET`
  потрібен також для локальних TCP/UDP-сокетів.
- Android-збірка приймає приватні IPv4, loopback і link-local адреси. Це не
  замінює автентифікацію: потрібні довірена мережа та пароль сервера.
- Публічний хостинг і перенаправлення портів роутера до цієї схеми не входять.

## Збирання з коду

Для збирання потрібні комп'ютер та інтернет для завантаження SDK/Gradle.
Для роботи встановленого APK — ні.

| Інструмент | Версія проєкту |
| --- | --- |
| JDK | 17, повний JDK із `javac` |
| Gradle | 8.11.1, включений wrapper |
| Android Gradle Plugin | 8.9.1 |
| Android SDK Platform | 35 |
| Android SDK Build-Tools | 35.0.0 |
| Android NDK | 27.0.12077973 |
| SDK CMake | 3.22.1 |

1. Клонувати репозиторій:

   ```bash
   git clone https://github.com/JekaK/Local-Mumble-Server.git
   cd Local-Mumble-Server
   ```

2. Відкрити корінь репозиторію в Android Studio; вибрати JDK 17 для Gradle.
3. Встановити наведені SDK, Build-Tools, NDK і CMake через SDK Manager.
4. Налаштувати шлях SDK через Android Studio, `ANDROID_HOME` або локальний
   `local.properties`. Не комітити шлях із конкретного комп'ютера.
5. Виконати збирання та lint:

   ```bash
   ./gradlew assembleDebug lintDebug
   ```

   На Windows: `gradlew.bat assembleDebug lintDebug`.

6. Встановити `app/build/outputs/apk/debug/app-debug.apk` на тестовий телефон.
   За наявності USB debugging і Android platform-tools можна використати:

   ```bash
   adb install -r app/build/outputs/apk/debug/app-debug.apk
   ```

Код нативних залежностей включений у репозиторій. Gradle-задачі
`buildServer_*` автоматично збирають і пакують сервер для трьох архітектур.
На телефоні не потрібно встановлювати Termux чи окремий серверний рушій.
Для production-розповсюдження потрібно налаштувати та зберегти власний
release signing key; він не включений у проєкт. Локальний debug-ключ може
відрізнятися від ключа готового APK, тому Android може відмовити в оновленні
поверх нього. Видалення застосунку очищає налаштування та TLS-сертифікат.

## Перевірки

[VALIDATION.md](VALIDATION.md) містить записані результати та обмеження.

Окремо відтворити нативні тести на Linux:

```bash
cmake -S app/src/main/cpp -B app/build/host -DCMAKE_BUILD_TYPE=Release
cmake --build app/build/host --target umurmur_server -j 4
python3 tests/protocol_smoke.py --binary app/build/host/libumurmur_server.so
```

Для тестів зашифрованого UDP встановити `cryptography` у Python virtual environment:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install cryptography
.venv/bin/python tests/protocol_smoke.py --binary app/build/host/libumurmur_server.so --udp-voice
```

Тести перевіряють автентифікацію, повідомлення протоколу та двосторонню
передачу Opus-пакетів. Затримку від мікрофона до навушників вони не вимірюють.
`tests/android_smoke.py` потребує Android 15 x86-64 AVD із назвою `mumble_test`.
У початковому середовищі його запуск заблокувало довге завантаження
емулятора; це не зараховано як пройдений тест.
