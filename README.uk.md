# Local Mumble Server

**Українська** · [English](README.md)

Локальний голосовий сервер на Android-телефоні. Увімкніть точку доступу, запустіть сервер і підключіть інші пристрої через Mumble-сумісні клієнти. Власник телефона може одночасно говорити через окремий клієнт на тому самому телефоні.

**У версії 2 вбудований uMurmur замінено власною реалізацією на Kotlin.** Android-застосунок і серверна логіка написані на Kotlin. Немає виконуваного Murmur/uMurmur, native-бібліотеки голосового сервера, NDK, CMake, Termux, потреби в root чи завантаженні рушія під час запуску.

[Завантажити APK](https://github.com/JekaK/Local-Mumble-Server/raw/refs/heads/master/downloads/LocalMumbleServer-2.0.0-beta3.apk) · [Встановлення](#покрокове-встановлення) · [Усунення-проблем](#усунення-проблем) · [Звіт-перевірки](VALIDATION.md)

| Android | Версія | Виконання | Голосовий транспорт |
| --- | --- | --- | --- |
| 8.0+ | 2.0.0-beta3 | Kotlin-сервер та Compose UI | TLS 1.2+ і зашифрований UDP |

> **Бета-версія:** автоматичні тести перевіряють протокол Kotlin-сервера та передавання голосових пакетів. Вони не вимірюють затримку від мікрофона до динаміка, місткість реального класу чи сумісність з усіма iPhone-клієнтами. Роботу на фізичних Android/iPhone ще потрібно перевірити. Фактичні результати й обмеження наведені у [VALIDATION.md](VALIDATION.md).

## Як це працює

1. Системна точка доступу Android створює локальну мережу.
2. Foreground-сервіс виконує Kotlin-сервер усередині процесу застосунку.
3. Клієнт викладача на цьому телефоні підключається до `127.0.0.1:64738`.
4. Інші пристрої підключаються до IP-адреси телефона в мережі хотспота.
5. Сервер перевіряє учасників і пересилає між ними закодовані голосові пакети.

Mumble тут — **протокол клієнтів**. Murmur і uMurmur — окремі серверні реалізації; у цій версії їх немає. Це власний невеликий сервер з одним каналом, а не офіційний сервер Mumble.

Застосунок **не має вбудованого голосового клієнта**. Для розмови встановіть клієнт на телефон власника й на кожен пристрій учасника.

## Вимоги

| Компонент | Вимога |
| --- | --- |
| Телефон-сервер | Android 8.0+ з робочою Wi-Fi-точкою доступу |
| Архітектура | Універсальний APK: ARMv7, ARM64, x86 та x86_64; Compose містить графічну бібліотеку AndroidX |
| Учасники | Mumble-сумісні клієнти з TLS 1.2+ |
| Кодеки | Opus у всіх клієнтів або спільна версія CELT у всіх клієнтів |
| Мережа | Локальний IPv4; TCP і UDP використовують той самий порт |
| Інтернет | Для початкового завантаження застосунків і залежностей збірки; для розмови не потрібен |
| RAM/CPU | Мінімальні апаратні вимоги й місткість класу ще не виміряні |

Коли всі клієнти підтримують Opus, сервер обирає Opus. Старий CELT-клієнт допускається, якщо вся група має спільну версію CELT. За відсутності спільного кодека клієнт отримує чітку відмову. **Перекодування аудіо немає.**

Сервер використовує поширений старий формат голосових UDP-пакетів Mumble. Він оголошує сумісність з протоколом Mumble 1.2.4; версія самого застосунку — 2.0.0-beta3.

## Покрокове встановлення

### 1. Завантажте застосунки заздалегідь

1. Завантажте [LocalMumbleServer-2.0.0-beta3.apk](https://github.com/JekaK/Local-Mumble-Server/raw/refs/heads/master/downloads/LocalMumbleServer-2.0.0-beta3.apk).
2. Для Android встановіть [Mumla](https://mumla-app.gitlab.io/) через [F-Droid](https://f-droid.org/packages/se.lublin.mumla/) або офіційне джерело.
3. Для iPhone встановіть Mumble-сумісний клієнт і перевірте його із цим сервером до уроку.
4. Якщо власник телефона говоритиме, встановіть клієнт і на телефон-сервер.
5. Збережіть APK на пристрої: робота сервера не потребує інтернету.

Контрольна сума APK: [downloads/SHA256SUMS](downloads/SHA256SUMS). Публікується **бета з debug-підписом**, не реліз Google Play.

**Перехід із попереднього опублікованого APK:** beta3 має інший debug-сертифікат підпису.
Перед встановленням beta3 видаліть старий серверний застосунок. Його налаштування
й TLS-ідентичність очистяться; окремий голосовий клієнт видаляти не потрібно.

### 2. Встановіть APK на Android

1. Відкрийте завантажений APK.
2. Якщо система просить, дозвольте браузеру або файловому менеджеру встановлення невідомих застосунків.
3. Встановіть і відкрийте **Локальний Mumble сервер**.
4. Надайте дозвіл на сповіщення. Постійне сповіщення показує роботу сервісу й містить кнопку зупинки.
5. Якщо в налаштуваннях батареї є режим без обмежень для цього застосунку, увімкніть його на час заняття.

Потрібні дозволи мережі, foreground-сервісу, wake lock і сповіщень. Доступу до мікрофона сервер не запитує.

### 3. Увімкніть точку доступу

1. Натисніть **Відкрити налаштування точки доступу** або відкрийте відповідний розділ Android.
2. Задайте назву мережі й пароль WPA2/WPA3.
3. Увімкніть хотспот; вимкніть його автоматичне вимкнення, якщо така опція доступна.
4. Підключіть пристрої учасників до цієї Wi-Fi-мережі.
5. Якщо Android/iOS повідомляє, що інтернету немає, залиште підключення до цієї мережі.

Кількість Wi-Fi-клієнтів обмежується телефоном та його ОС. Збільшення ліміту учасників у застосунку не збільшує системний ліміт хотспота.

### 4. Запустіть Kotlin-сервер

1. Залиште порт **64738**, якщо його не займає інший застосунок.
2. Виберіть максимум учасників: типово **30**, налаштування допускає 2–100.
3. Спочатку залиште ліміт голосового трафіку **48000 біт/с**.
4. За потреби задайте пароль сервера. Це окремий пароль, не пароль Wi-Fi.
5. Натисніть **Запустити сервер**.
6. Дочекайтеся **Сервер працює**.

Перший запуск створює самопідписаний TLS-сертифікат у приватному сховищі застосунку. Статус роботи з’являється лише після відкриття TCP- та UDP-сокетів.

Ліміт трафіку повідомляється клієнтам і контролюється для кожного користувача через token bucket. У ньому враховується запас на службові байти пакетів; це **не гарантований бітрейт аудіокодека**.

### 5. Підключіть клієнт викладача

Створіть з’єднання у Mumla на телефоні-сервері:

| Поле | Значення |
| --- | --- |
| Адреса | `127.0.0.1` |
| Порт | `64738` або встановлений вами |
| Ім’я | Унікальне, наприклад `Teacher` |
| Пароль | Необов’язковий пароль сервера |

Якщо клієнт показує запит, прийміть самопідписаний сертифікат цього локального сервера. Канал — **Клас**. Навушники й push-to-talk зменшують відлуння. Клієнт викладача займає один слот учасника.

### 6. Підключіть учасників

1. Підключіть їхні телефони до хотспота викладача.
2. У серверному застосунку прочитайте IP під **Для учнів**.
3. У клієнті вкажіть цей IP, порт, унікальне ім’я й пароль сервера.
4. Прийміть очікуваний локальний сертифікат.
5. Переконайтеся, що відкрився канал **Клас** і видно інших учасників.

| Де працює клієнт | Яку адресу вводити |
| --- | --- |
| На телефоні-сервері | `127.0.0.1` |
| На пристрої у хотспоті сервера | IP Android-телефона в мережі хотспота |
| У спільній мережі звичайного роутера | LAN IP Android-телефона, **не** шлюз роутера |

Якщо IP хотспота не видно, відкрийте деталі Wi-Fi на пристрої учня: **Шлюз/Router** зазвичай указує на телефон, який роздає хотспот. Це правило не підходить для окремого роутера.

На телефоні учня `127.0.0.1` означає сам телефон учня. Після перезапуску точки доступу IP сервера може змінитися.

### 7. Перевірте роботу до уроку

1. Спочатку підключіть викладача й одного учня.
2. Перевірте звук в обидва боки, а не лише статус підключення.
3. Повторіть перевірку з погашеним екраном і відкритим голосовим клієнтом викладача.
4. Додавайте учасників поступово.
5. Якщо потрібні iPhone, перевірте конкретний iPhone-клієнт окремо.
6. Змінюйте ліміт трафіку й аудіоналаштування після успішної базової перевірки.

Foreground-сервіс і wake lock допомагають утримувати процес активним. Обмеження виробника телефона все одно можуть його зупинити. Максимум 100 у налаштуваннях не є результатом тесту на 100 пристроях.

## Перевірка підключення iPhone

**Якщо iOS залишається на “Connecting”, а сервер уже рахує учасника, спочатку встановіть beta3.** Лічильник означає прийняту авторизацію, а не підтвердження отримання `ServerSync` клієнтом. Зелений статус означає, що TCP/UDP-сокети сервера працюють.

Раніше сервер передавав тип, довжину й тіло кожного кадру окремими TLS-записами. [Читач заголовків у старому MumbleKit](https://github.com/mumble-voip/mumblekit/blob/b9085ec88d305ed28be89ceca14d53670769bcf9/src/MKConnection.m#L793-L830) відкидає результат читання, якщо отримав менше шести байтів заголовка. У beta3 весь кадр передається одним записом у TLS-потік, щоб усунути цю несумісність. Регресійні тести відтворюють поведінку читача через справжні JVM TLS-сокети; тест на фізичному iPhone ще потрібен.

- Дозвольте локальну мережу для клієнта в iOS: [інструкція Apple](https://support.apple.com/en-us/102229).
- Перевірте підключення до хотспота, IP сервера й порт.
- Прийміть новий сертифікат. Версія 2 використовує іншу серверну ідентичність, тому відбиток відрізняється від версії 1.
- Відкрийте **Журнал сервера**: він розрізняє TLS-з’єднання, успішний вхід і причину відмови.
- “No common audio codec” означає, що клієнти не мають спільного кодека. Сервер не перекодовує Opus у CELT.
- [Старий Mumble для iPhone](https://apps.apple.com/us/app/mumble/id443472808) має [upstream без активної підтримки](https://github.com/mumble-voip/mumble-iphoneos). Сумісність саме цієї програми треба перевіряти на пристрої.

Без такого тесту немає підтвердження реальної iPhone-сумісності чи затримки звуку.

## Усунення проблем

| Симптом | Перевірка або виправлення |
| --- | --- |
| Сервер не запускається | Журнал, зайнятий порт, допустимі налаштування |
| Connecting, а сервер рахує цього клієнта | Встановіть beta3 з виправленням TLS-кадрів; прийміть новий сертифікат і підключіться знову |
| Connecting без авторизованого учасника | Правильний IP і порт, хотспот, дозвіл локальної мережі, сертифікат, журнал |
| Помилка TLS | Потрібен TLS 1.2+; перевірте запит прийняття сертифіката |
| Wrong server password | Пароль сервера, не пароль точки доступу |
| Username already in use | Унікальне ім’я для кожного пристрою; регістр не розрізняється |
| Server full | Відключіть зайві клієнти або збільште серверний ліміт |
| No common audio codec | Opus-клієнти для всієї групи або спільна версія CELT |
| Підключено, але звуку немає | Push-to-talk, дозвіл мікрофона клієнта, mute/deafen, перевірка двох пристроїв |
| Затримка або обриви | Сигнал Wi-Fi, місткість хотспота, енергозбереження, аудіоналаштування клієнта |
| Зупинка з погашеним екраном | Обмеження батареї й автоматичне вимкнення хотспота |
| Змінився сертифікат | Очікувано під час переходу зі старої native-версії на Kotlin |
| APK не оновлюється поверх старого | Можуть відрізнятися debug-ключі підпису |

Якщо UDP недоступний, підтримується передавання через TLS/TCP. Після підтвердження UDP сервер використовує його; отримання тунельованого голосового пакета переводить цього клієнта назад на TLS. Неактивна UDP-адреса протухає через 15 секунд.

## Можливості, приватність і обмеження

Реалізовано: один голосовий канал, унікальні гостьові імена, необов’язковий пароль, лічильник учасників, узгодження кодека, TLS-керування й голос, OCB2-AES128 UDP, ping, ресинхронізація nonce, self-mute/self-deafen, обмеження трафіку та зупинка зі звільненням сокетів.

Не реалізовано: зареєстровані облікові записи, адміністрування ACL, створення каналів, kick/ban, текстовий чат, whisper, запис, вебдоступ, перекодування аудіо й вбудований мікрофонний клієнт.

Сервер пересилає закодований голос, не декодує й не записує його. Налаштування, пароль і TLS-ідентичність зберігаються в Android sandbox; резервне копіювання вимкнене. Журнал містить інформацію про з’єднання й учасників, але не аудіо чи серверні паролі. Приватний TLS-ключ лежить у приватному сховищі застосунку.

Приймаються лише loopback, приватні та link-local IPv4-адреси. Фільтр адрес **не замінює авторизацію**; захистіть хотспот і задайте пароль сервера.

## Збірка й тести

Потрібні **JDK 17**, **Gradle 8.11.1**, **AGP 8.9.1**, **Kotlin 2.1.20**, **Android SDK 35 / Build Tools 35.0.0**. NDK і CMake не потрібні.

```bash
git clone https://github.com/JekaK/Local-Mumble-Server.git
cd Local-Mumble-Server
./gradlew :server-core:test :app:testDebugUnitTest :app:assembleDebug :app:lintDebug
```

Для Windows використовуйте `gradlew.bat`. Шлях SDK задається в Android Studio або локальному файлі `local.properties`, який не комітиться. Перша збірка завантажує залежності через інтернет.

APK: `app/build/outputs/apk/debug/app-debug.apk`.

Запуск того самого Kotlin-ядра на комп’ютері для розробки:

```bash
./gradlew :server-core:installDist
server-core/build/install/server-core/bin/server-core 64738 school-test
```

Третій необов’язковий аргумент задає каталог серверної ідентичності. Цей launcher потрібен для протокольних тестів; Android виконує ядро безпосередньо у foreground-сервісі.

Збірка на іншому комп’ютері використовує його debug-ключ. APK з іншим підписом не встановиться поверх старого; видалення застосунку очищає дані й сертифікат.

**Опублікований beta3 підписаний іншим debug-ключем, ніж попередні APK.** Перед
встановленням видаліть попередній серверний застосунок: його налаштування та
TLS-ідентичність очистяться. Окремий голосовий клієнт видаляти не потрібно.

## Архітектура Android

`MainActivity` містить лише `FragmentContainerView`. `ServerFragment` створює
`ComposeView` зі стратегією `DisposeOnViewTreeLifecycleDestroyed`, обробляє
дозвіл сповіщень, буфер обміну й відкриття системних налаштувань. Стан
`ServerViewModel.uiState` збирається через `collectAsStateWithLifecycle`.
XML-розмітки екрана немає.

ViewModel перевіряє форму, надсилає команди запуску/зупинки та надає єдиний
незмінний стан через `StateFlow`. Повторні натискання блокуються до підтвердження
команди сервісом. Числові поля використовують `SavedStateHandle`. Незбережений
пароль лишається в пам’яті: переживає звичайний поворот екрана разом із ViewModel,
але не записується в Bundle збереженого стану. Прийняті налаштування зберігаються
в попередньому приватному файлі preferences `MainActivity`.

Контракт `ServerRepository` відділяє ViewModel від Android API. Android-реалізація
працює з налаштуваннями, командами foreground-сервісу та спостереженням за його
станом. IP-адреси й UDP перевіряються на `Dispatchers.IO`; опитування припиняється
без підписників. Сервер працює у foreground-сервісі незалежно від життєвого циклу
UI. Залежності передаються через `AppContainer` і явну фабрику ViewModel.

## Структура й ліцензії

| Шлях | Призначення |
| --- | --- |
| `app/.../presentation/main/` | Activity з контейнером для відновлюваного Fragment |
| `app/.../presentation/server/` | Fragment, Compose-екран, стан UI та ViewModel |
| `app/.../presentation/theme/` | Тема Compose Material 3 |
| `app/.../domain/` | Налаштування, стан сервера, валідація та контракт repository без Android API |
